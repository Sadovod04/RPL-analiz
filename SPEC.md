# SPEC.md — RPL-analiz

## 1. Цель
Модель, которая по ранней карьерной статистике футболиста из академии России
(возраст 11–21) оценивает **вероятность когда-либо закрепиться в РПЛ**. Это задача
**ранжирования потока кандидатов** с честной калибровкой вероятностей и оценкой
неопределённости — «выдать топ-N перспективных из потока», а не гарантированный
вердикт по одному игроку. Проект портфельный, не production.

## 2. Задача моделирования
- Не бинарный классификатор «заиграет / не заиграет» в проде.
- Модель ранжирования + калиброванная вероятность + (в M5) ожидаемое время события.
- Реалистичная цель — топ-N перспективных из когорты, с явно проговорённой неопределённостью.

## 3. Таргеты
**Основной (бинарный):**
- `1` — игрок когда-либо набрал **≥ 200 минут в РПЛ**
- `0` — не набрал **и** возраст сейчас **≥ 26 лет**
- иначе (не набрал, младше 26) — **censored**: в бинарное обучение не идёт, идёт в survival
- пороги `200` и `26` — в конфиге (`config/settings.toml`), ревизия после EDA

**Вторичный (порядковый):** «не заиграл / низшие лиги (дошёл до Первой лиги или
проф. уровня) / РПЛ». Обогащает сигнал, в основную метрику не входит.

**Survival (M5):** время события = возраст дебюта в РПЛ; censored = ещё не дебютировал.
Даёт вероятность пробива к любому возрасту.

## 4. Выборка
- **Все академии России** — Зенит, Спартак, ЦСКА, Локомотив, Динамо, Краснодар,
  Чертаново, Академия Коноплёва, Рубин, Ростов, Крылья Советов и др.
- **Универс академий** = клубы, заявляющие команды в ЮФЛ-1/2/3 + академии клубов
  РПЛ / Первой лиги. Список в конфиге, формируется из участников ЮФЛ.
- **Годы рождения 1990–2004** — обучающая выборка (исход в основном определился).
- **2005+** — не в обучение, а в выход продукта: «кого модель поднимает в топ сейчас».
- Точка отсчёта фич — **11 лет**.

## 5. Источники данных

**Ядро (M1a — реализовано):**
| Источник | Что даёт | Как берём |
|---|---|---|
| **Transfermarkt tmapi** (`tmapi.transfermarkt.technology`) | Мастер-данные (ДР, позиция, рост, нога, паспортное имя кириллицей, `formerClubsNote`=youth clubs, рыночная стоимость); `performance-game` — каждый матч карьеры: турнир, сезон, минуты, голы, ассисты, возраст. **Включает `RUJL` (ЮФЛ) — частично замещает youfl.ru.** Агрегируется до (сезон, турнир). | `httpx`, без WAF, rate-limited |
| **www.transfermarkt.com** (kader) | Исторические составы академий по сезонам — только для discovery id игроков | headless Chromium (Playwright), обходит AWS WAF |
| **Wikipedia** (`ru.wikipedia.org`, MediaWiki API) | Замена youfl.ru: статьи по сезонам ЮФЛ → участники (сид академического универса) + турнирная таблица (сила клуба по сезону) | `httpx` |
| **resolver** | Блокировка по году рождения + fuzzy-match нормализованных имён (транслит кириллицы), union-find → стабильный `player_id` | — |

> **youfl.ru недоступен** из не-RU сети (TLS-reject). `ingest/sources/youfl.py` — заглушка, отложен в M1b (реализуется при запуске из РФ). Структура ЮФЛ: ЮФЛ-1 (U17/U18), ЮФЛ-2 (U16), ЮФЛ-3 (U15).

**Обогащение (M1b, параллельно M2–M4):**
| Источник | Что даёт |
|---|---|
| **РФС** (rfs.ru) | Вызовы в юношеские сборные U16–U19, первенства СШ/СШОР |
| **Региональные федерации (МРО)** | Юношеские первенства U11–U14 под конкретные пробелы (низкий приоритет — ЮФЛ покрывает всю РФ с U15) |
| **Sofascore** (недок. API) | Рейтинги игроков, детали матчей (осторожно с ToS, rate limit) |
| **FBref** (worldfootballR) | Продвинутые метрики (xG/xA, progressive) для взрослых лиг |

**Юридически:** rate limiting + backoff между запросами; не публикуем сырой
скрейпленный датасет (только код скрейпера и агрегированные фичи); не выдаём за
production-сервис.

## 6. Пайплайн
```
scrape (TM, ЮФЛ, …) → Postgres (raw) → resolve сущностей
  → build_features (строгий time cutoff) → labels (осн. + вторичн. + censoring)
  → Parquet (processed) → модели → eval → отчёт
```
Партиционирование сырья по «сезону сбора». Пересборка фич без повторного скрейпинга.

## 7. Feature engineering

**Базовые (есть у всех):**
- Возраст в каждом сезоне
- Позиция (one-hot: GK / CB / FB / CM / W / ST)
- Рост, вес (если есть)
- Минуты, голы, ассисты, (голы+ассисты) на 90 — по возрастным категориям
  **U13 / U15 / U17 / U19 / U21**
- Прогрессия минут год к году (тренд роли в составе)
- Клуб и его **историческая конверсия академии** (доля выпускников, дошедших до РПЛ) —
  считается **time-aware**, только по когортам с известным исходом до года предсказания
- Легионер / местный
- Вызовы в юношеские / молодёжные сборные

**Продвинутые (если достанем):**
- xG / xA на 90 в молодёжке
- Рыночная стоимость **на момент cutoff-возраста** (историческая, не текущая)

**Запрещены (data leakage):**
- Текущий клуб на момент сбора данных
- Вызов во взрослую сборную (tautology с «уже заиграл»)
- Текущая рыночная стоимость (поднимается после прорыва)
- Любая фича, посчитанная по данным после cutoff-возраста

**Правило:** строгий time cutoff — все фичи считаются по данным строго до целевого
возраста, через единую функцию-фильтр (`features/time_cutoff.py`).

## 8. Методологические гардрейлы (зашиты с M2)
- **Строгий time cutoff** — единая функция `features/time_cutoff.py`, через неё
  проходит любой сезон перед агрегацией
- **Temporal split** на финальной оценке (train — исход разрешился раньше года T,
  test — позже), не random
- **Group k-fold по `player_id`** для тюнинга — один игрок не течёт между фолдами
- **Censoring-флаг** в датасете с M2 (чтобы survival не требовал пересборки)
- **`eval/leakage_check.py`** — тест, падающий при попадании запрещённой фичи в матрицу
- Явно включаем «выпавших» игроков — последняя зафиксированная лига это маркер
  негативного исхода, а не пропуск; выборку не режем по «объёму доступных данных»
- **Дисбаланс:** class weights в лоссе; метрики PR-AUC / Recall@TopK / Brier, не
  accuracy; SMOTE/ADASYN — с осторожностью; stratified k-fold

## 9. Модели
1. **Baseline** — логистическая регрессия на простых фичах + **«наивный скаут»**
   (ранжирование по рыночной стоимости как есть). Модель обязана побить наивного скаута.
2. **CatBoost** — нативная работа с категориальными; тюнинг Optuna; group k-fold по
   игроку; **SHAP** (importance + interaction), partial dependence plots.
3. **Survival (M5)** — Cox Proportional Hazards + Random Survival Forest
   (lifelines / pycox); из hazard-функции — вероятность пробива к любому возрасту.
4. **Интерпретация** — какие фичи реально двигают предсказание; PDP по ключевым.

## 10. Валидация и метрики
- **Split:** temporal (train — судьба определилась до года T; test — после).
- **Group k-fold по игроку** внутри train для тюнинга.
- **Метрики:**
  - **PR-AUC** — основная (из-за дисбаланса)
  - **Brier score** + **calibration plot** — вероятности должны быть осмысленны
  - **Recall@Top-20** — сколько реальных будущих игроков РПЛ попало в топ-20
    предсказанных. Пул кандидатов = все игроки академий выборки, кому в год T
    исполнилось Y лет.

## 14. Риски и честные ограничения
- **Дисбаланс:** база пробива из академии в РПЛ — единицы процентов. Выборка
  небольшая по меркам ML (несколько тысяч игроков) — шум ожидаем и нормален для темы
  с высокой внутренней неопределённостью (травмы, форма, решения тренера).
- **Данные до U14 почти отсутствуют** → фичи 11–13 лет разреженные; основной сигнал
  набирается с ~14 лет там, где есть покрытие, и улучшается по мере подключения источников.
- **Открытые данные по молодёжкам РФ скудны и неструктурированы** — пропуски
  неизбежны, CatBoost обрабатывает их нативно.
- Это **не про точный прогноз по одному игроку**, а про статистически осмысленное
  ранжирование потока кандидатов. Проект так и позиционируется.
