# METHODOLOGY.md — RPL-analiz

Как именно проект превращает сырую статистику в оценку перспективности и как эта
оценка проверяется. Здесь — вся логика: какие берутся факторы, по каким формулам
они считаются, как устроены измерения и метрики. Это дополнение к
[`SPEC.md`](SPEC.md) (что делаем) и [`REPORT.md`](REPORT.md) (что получилось).

Ничего не берётся «из головы»: каждая фича приходит из конкретного поля источника
через одну функцию сборки ([`features/build_features.py`](features/build_features.py)),
каждое число в отчёте воспроизводится скриптом из раздела «Воспроизведение» в
`REPORT.md`.

---

## 1. Что именно измеряется

**Величина, которую оцениваем:** для футболиста из российской академии —
вероятность `P(закрепиться в РПЛ)`, где «закрепиться» = когда-либо набрать
**≥ 200 минут в РПЛ** за карьеру.

**Тип задачи:** ранжирование потока кандидатов + калиброванная вероятность. НЕ
бинарный вердикт по одному игроку. Практический результат — «топ-N перспективных
из когорты этого года».

**Три формализации одного вопроса** ([`features/labels.py`](features/labels.py)):

| Таргет | Формула | Кто использует |
|---|---|---|
| `target` (бинарный) | `1`, если `rpl_minutes_ever ≥ 200`; `0`, если `< 200` **и** `current_age ≥ 26`; иначе `−1` (censored) | CatBoost, logreg |
| `pro_target` (бинарный) | `1`, если игрок набрал > 0 минут в РПЛ / ФНЛ / ФНЛ-2; `0`, если нет **и** `current_age ≥ 26`; иначе `−1` | те же |
| `ordinal_target` | `rpl` / `lower_leagues` / `none` | вспомогательный сигнал |
| survival `(duration, event)` | `duration` = возраст дебюта в РПЛ, если был; иначе `current_age`. `event` = 1, если дебют состоялся | Cox PH |

Пороги `200` минут и `26` лет — в [`config/settings.toml`](config/settings.toml)
→ `[target]`. `current_age = as_of_year − birth_year`.

**Censored (`−1`)** — игрок ещё не набрал 200 минут, но и не «состарился» (моложе
26). Судьба не решена → в бинарное обучение не идёт (`features/split.py:drop_censored`),
идёт только в survival и в пул «перспективных» на дашборде.

## 2. Конвейер данных

```
источники → raw_document (JSONB) → resolver → типизированные таблицы → build_features → features.parquet → модель
```

### 2.1. Источники

| Источник | Что берём | Доступ |
|---|---|---|
| **Transfermarkt tmapi** (`tmapi.transfermarkt.technology`) | мастер-данные (ДР, позиция, рост, гражданство, паспортное имя кириллицей); `performance-game` — каждый матч карьеры: турнир, сезон, минуты, голы, ассисты, возраст в сезоне; рыночная стоимость | `httpx`, rate-limited, без WAF |
| **www.transfermarkt.com** (`kader`) | исторические составы академий — только для обнаружения `player_id` | headless Chromium (Playwright), обход AWS WAF |
| **ru.wikipedia** (MediaWiki API) | статьи сезонов ЮФЛ (участники + таблицы); статьи-персоналии игроков (Фаза B: дата создания статьи, категории, «Достижения») | `httpx` |

Недоступны отсюда: youfl.ru (TLS-reject с не-RU IP), youthleague.ru (то же),
РФС/Sofascore/FBref (403 / низкий ROI) — адаптеры-скелеты есть.

### 2.2. Entity resolution ([`ingest/resolve.py`](ingest/resolve.py))

Один физический игрок может прийти из нескольких источников под разными
написаниями. Склейка:

1. **Нормализация имени** `normalize_name`: нижний регистр; «Фамилия, Имя» →
   «имя фамилия»; транслит кириллицы по фиксированной таблице `_CYR2LAT`;
   удаление диакритики (NFKD → ASCII); только `[a-z0-9 ]`.
2. **Блокировка** по году рождения — сравниваются только записи с одинаковым
   `birth_year` (или обе без года — тогда порог строже).
3. **Fuzzy-match** внутри блока: `rapidfuzz.token_sort_ratio` между
   нормализованными именами (и паспортным именем кириллицей). Порог
   `MATCH_THRESHOLD = 87` (для блока «год неизвестен» +6).
4. **Кластеризация** union-find: пары выше порога объединяются.
5. **Стабильный id**: `player_id = sha1("<отсортированные токены канонического имени>|<год>")[:16]`.

### 2.3. Объём

Полный краул (`ingest.run_ingest --academy-seasons 2013-2026 --fast --build`):
~4000 обнаруженных id → **3982 игрока** в `features.parquet`, 521 академия, годы
рождения ~1995–2010, **59 078** строк «сезон-в-лиге». Краул resumable
(чекпойнт + пропуск уже собранных).

## 3. Временная отсечка (time cutoff) — центральный гардрейл

**Правило:** признак может использовать только то, что наблюдалось **строго до**
того, как игроку исполнилось `modeling_cutoff_age` (= **19 лет**,
`config/settings.toml` → `[features]`).

**Реализация:** одна протестированная функция
[`features/time_cutoff.py`](features/time_cutoff.py):

```python
def before_cutoff(df, cutoff_age, age_col="age_at_season"):
    mask = df[age_col].notna() & (df[age_col] < cutoff_age)
    return df.loc[mask].copy()
```

Каждая строка сезона проходит через неё **до** любой агрегации в фичу. Строка без
возраста выбрасывается (нельзя доказать, что она pre-cutoff). Держать это в одной
крошечной функции — вся защита от утечки по времени.

**Точка старта** — 11 лет (`cutoff_age_start`); данных младше U15 почти нет.

## 4. Признаки (41 вход модели)

Строятся в `features/build_features.py:build_feature_matrix`. Ниже — все, по
группам: **определение · формула · источник · зачем · оговорка**.

Возрастные корзины (`_BUCKET_EDGES`): `U13` = возраст < 13, `U15` = [13,15),
`U17` = [15,17), `U19` = [17,19), `U21` = [19,21). В матрицу для cutoff = 19
реально попадают U13–U19.

Уровень лиги (`_LEVEL_RANK`, ординал «ближе к основе»): ЮФЛ = 1, Вторая лига = 2,
Первая лига / РПЛ-стыки = 3, РПЛ = 4.

### 4.1. Статические атрибуты игрока

| Фича | Определение | Источник |
|---|---|---|
| `position` | амплуа (GK/DF/MF/FW), категориал | TM мастер |
| `position_detail` | детальное амплуа (напр. «Centre-Back»), категориал | TM мастер |
| `height_cm` | рост, см | TM мастер |
| `is_foreigner` | 1, если не РФ-паспорт | TM мастер |
| `birth_quarter` | `ceil(месяц_рождения / 3)`, 1–4 | ДР |
| `rel_age_frac` | `(12 − месяц_рождения) / 11`, диапазон 0…1; выше = родился раньше в календарном году = относительно старше внутри возрастной группы (отсечка РФС — 1 января) | ДР |

**Зачем `birth_quarter` / `rel_age_frac`:** relative age effect. В наборе академий
Q1 = 37.6% разрешённых игроков против Q4 = 14.7% (переотбор рождённых в начале
года). Среди дошедших до РПЛ распределение выравнивается → поздно рождённый,
прошедший отбор, — чуть *лучшая* ставка. Сигнал слабый, знак верный.

### 4.2. Юношеская статистика (агрегаты pre-cutoff, `_youth_features`)

`g` = все pre-cutoff строки игрока; `tot_min` = сумма минут.

| Фича | Формула |
|---|---|
| `youth_seasons` | число уникальных сезонов |
| `youth_minutes_total` | `Σ minutes` |
| `youth_goals_total` | `Σ goals` |
| `youth_ga_per90` | `90 · (Σ goals + Σ assists) / tot_min` (0, если `tot_min = 0`) |
| `youth_minutes_trend` | наклон OLS-прямой `minutes ~ age_at_season` (`_slope` = `polyfit` степени 1; 0, если < 2 точек) |
| `played_youth_league` | `True`, если хоть одна строка в лиге «Russian Youth League» (ЮФЛ) |
| `best_level_pre_cutoff` | `max(_LEVEL_RANK[league])` по всем pre-cutoff строкам |
| `minutes_{U13..U21}` | `Σ minutes` в этой возрастной корзине |
| `ga_per90_{U13..U21}` | `90 · (goals + assists) / minutes` в корзине |

**Зачем:** сколько и на каком уровне играл юным, насколько результативно, растёт
ли нагрузка. `best_level_pre_cutoff` — стабильно топ-1/2 по SHAP.

### 4.3. Траектория и роль (`_trajectory_features`)

Норма лиги-сезона (`_league_season_norms`): по каждой паре (лига, сезон) —
средний возраст и максимум матчей; группы < 8 игроков получают NaN (шумная база).

| Фича | Формула · зачем |
|---|---|
| `min_age_gap_vs_peers` | `min` по pre-cutoff сезонам от `(возраст_игрока − средний_возраст_лиги-сезона)`. Отрицательное = играл на возраст выше своего. Входит в топ-8 SHAP |
| `mean_age_gap_vs_peers` | то же, среднее |
| `matches_share_min` / `_mean` | `min` / `mean` от `matches / max_matches_в_лиге-сезоне` (клип по 1.0). Прокси доступности (сколько «полного сезона» отыграл) |
| `minutes_dropoff_max` | по соседним pre-cutoff сезонам: `max((prev − cur) / prev)` при `prev ≥ 500`. Задумано как прокси травм; **на практике коррелирует с успехом положительно** (pro +0.31) — читается как «рано подняли на уровень». Оставлено с оговоркой |
| `had_minutes_collapse` | `True`, если был сезон ≥ 900 мин, а следующий pre-cutoff < 300 мин |
| `played_senior_pre_cutoff` | 1, если была pre-cutoff строка в РПЛ / ФНЛ / ФНЛ-2 |
| `first_senior_age` | `min(age_at_season)` среди таких строк; NaN, если не было. **Прироста к модели не дал** (уже в `best_level_pre_cutoff`), оставлен как интерпретируемый |
| `min_per_appearance` | `Σ minutes / Σ matches` по pre-cutoff (прокси старт-vs-замена) |
| `starter_share` | доля pre-cutoff сезонов, где `minutes/matches > 60` |

### 4.4. Контекст академии и рынка

| Фича | Формула · оговорка |
|---|---|
| `academy_conversion_rate` | `P(target = 1)` среди игроков той же академии из **более ранних** когорт (`birth_year <` текущего), без censored. NaN, если ранней истории нет. **Time-aware** — не видит будущее (`_academy_conversion_rate`). Оговорка: `academy_club` — свободный текст из TM `formerClubsNote`, поэтому фича слабая |
| `market_value_at_cutoff_eur` | последняя точка рыночной стоимости TM с датой, где `год − birth_year < cutoff_age` (`_market_value_at_cutoff`). Оговорка: у tmapi в основном только свежие точки → у большинства **пусто**. Это же — единственный вход «наивного скаута» |
| `cohort_year` | = `birth_year`, отдельной колонкой как **контроль эпохи** (лимит легионеров, отъезд иностранцев с 2022 сдвигают базовую вероятность). Во временном сплите тестовые когорты вне train-диапазона → модель может только экстраполировать тренд. Проба (§7): permutation importance ≈ 0 при SHAP #1 → это прокси, не рычаг, и **не** играет со сплитом |

### 4.5. «Признание» (Фаза B, `_attach_recognition`, источник — ru.wikipedia)

Независимая экспертная оценка, отдельная от голой статистики. Всё — строго
pre-cutoff.

| Фича | Формула |
|---|---|
| `wiki_article_pre_cutoff` | 1, если статья-персоналия в ru.wikipedia **создана** (первая ревизия) до того, как игроку исполнилось 19 |
| `wiki_youth_honours` | число строк «Достижения» с годом `≤ birth_year + 18` |
| `pre_cutoff_recognition_score` | `3 · wiki_article_pre_cutoff + 1 · wiki_youth_honours` |
| `recognition_count` | `wiki_article_pre_cutoff + wiki_youth_honours` |
| `any_recognition` | `pre_cutoff_recognition_score > 0` |

**Как матчится игрок к статье** ([`ingest/sources/wikipedia_players.py`](ingest/sources/wikipedia_players.py)):
поиск `generator=search` по «`<Фамилия Имя>` футболист» (отчество отброшено — в
TM оно часто неверное); кандидат принимается, только если (а) в категории
«Футболисты…» и (б) год рождения совпал (в тексте интро или в категории
«Родившиеся в YYYY году»).

**«Статья есть сейчас» / суммарные титулы — НЕ фичи** (это пост-фактум), сырые
`article_created_age` / `wiki_title` / `honours_years` / `nt_youth_levels`
заблокированы в `eval/leakage_check.py`.

**Выброшено:** `wiki_youth_national_team` — ru.wikipedia почти всегда вешает
только категорию «молодёжной сборной (до 21 года)», отдельных U17/U19 нет →
честно pre-cutoff не сделать. Этот сигнал — на источник РФС в поздней фазе.

**Важно — полу-циркулярность.** `recognition_count` коррелирует с
`market_value_at_cutoff_eur` на **0.70** (у фич §4.1–4.3 было ≤ 0.32). Из 204
разрешённых игроков с любым признанием **83.8%** дошли до РПЛ (база — 27.7%); со
статьёй до cutoff — 85% РПЛ. Сигнал хронологически до порога «200 мин», но
информационно близок к метке. Работает в первую очередь потому, что
`market_value_at_cutoff` в основном пустой, а факт ранней статьи — нет.

### 4.6. Пропуски

- Игрок без pre-cutoff сезонов → все агрегаты §4.2 = 0 (строка остаётся).
- `matches_share_*`, `first_senior_age`, `min_per_appearance`, `starter_share`,
  `market_value_at_cutoff_eur`, `academy_conversion_rate` → остаются NaN (CatBoost
  обрабатывает нативно; logreg-бейзлайн импутирует медианой).

## 5. Метки — как строится «правда» (`features/labels.py:attach_labels`)

Из `season_stats`:

- `rpl_minutes_ever = Σ minutes` по строкам с `is_rpl = True`.
- `rpl_debut_age = min(age_at_season)` по РПЛ-строкам с `minutes > 0`.
- `reached_pro_level` = есть ли строка с `minutes > 0` в {РПЛ, Первая лига,
  Вторая лига, РПЛ-стыки}.
- `current_age = as_of_year − birth_year`.
- `outcome_level` = высшая лига, где сыграл > 0 минут → {РПЛ / ФНЛ / ФНЛ-2 / не дошёл}.

Дальше — формулы таргетов из §1.

**Разрешённые исходы на полном крауле:** РПЛ — 542 дошли / 1001 нет / 2439 открыты;
проф. — 1591 / 493 / 1898.

## 6. Разбиение выборки

### 6.1. Временной сплит (`features/split.py:temporal_split`)

- **train** = когорты с `birth_year < test_cohort_from` (= 1999).
- **test** = `birth_year ∈ [test_cohort_from, test_cohort_to]` (= [1999, 2003]).
- censored-строки выбрасываются (`drop_censored`).

Смысл: обучаемся на прошлом, проверяемся на будущем — как в реальном
использовании.

`test_cohort_to` ограничивает тест сверху: у совсем молодых «разрешённых» игроков
почти все исходы — успехи (кто не заиграл, ещё не «состарился»), это раздувает
base rate. **Проба Фазы 3 показала: 2001–2003 всё равно без отрицательных
примеров → `test_cohort_to` надо ужать до 2000.**

### 6.2. GroupKFold при тюнинге (`models/gbm.py:group_kfold_scores`)

5 фолдов, группа = `player_id`. Один игрок никогда не оказывается и в train, и в
val одного фолда. Objective Optuna = средний PR-AUC по фолдам.

## 7. Модели

| Модель | Файл | Как устроена |
|---|---|---|
| **наивный скаут** | `models/baseline.py:naive_scout_scores` | ранжирование по `market_value_at_cutoff_eur`, пропуск → низший ранг. Планка, которую надо побить |

## 8. Метрики (`eval/metrics.py`)

Класс несбалансирован → **никогда accuracy**.

| Метрика | Формула / процедура | Зачем |
|---|---|---|
| **PR-AUC** | `average_precision_score` — площадь под precision-recall кривой | главная; устойчива к дисбалансу |
| **ROC-AUC** | `roc_auc_score` | вторичная |
| **Brier** | `mean((p − y)²)` | продукт выдаёт вероятность, а не только ранг |
| **Recall@Top-K** | `Σ y[top-K по score] / Σ y`; `K = 20` | «из реальных будущих РПЛ-игроков сколько попали в топ-20 модели» — это и есть продуктовый вопрос |
| **Recall@Top-K по годам когорт** | то же, но пул кандидатов = игроки этого года рождения отдельно | объединённое число прячет, что одни годы лёгкие, другие невозможные |
| **Калибровочная таблица** | 10 бинов по `p`; для каждого — `n`, средний прогноз, доля плюсов | насколько вероятность «настоящая» |
| **ECE** | `Σ_бины (n_бина / N) · |средний_прогноз − доля_плюсов|` | одно число калибровки |
| **Bootstrap 90% ДИ** | `B` ресэмплов теста с возвращением; для каждого — метрика; перцентили 5 и 95. Плюсов мало (~130) → точечная оценка обманчива | честная ширина неопределённости |
| **CV PR-AUC** | средний PR-AUC по 5 фолдам GroupKFold | оценка на train без переобучения |

Скрипт Фазы 3 — [`scripts/run_honest_eval.py`](scripts/run_honest_eval.py):
per-year recall + калибровка + bootstrap + проба `cohort_year` (переобучение без
неё + permutation importance).

## 9. Эвристика для детей регионов (нет карьеры → нет модели)

[`app/youth_features.py:youth_frame`]. Перцентили считаются **внутри каждого
источника** (у ФФ СПб — карьерные суммы, у Москвы — один сезон; глобальный ранг
просто награждал бы за «больше матчей залогировано»):

```
pers_score = 100 · (0.45 · перцентиль(голы_за_игру) + 0.30 · перцентиль(число_игр) + 0.25 · сила_клуба)
```

`сила_клуба` = 1.0 (Зенит/Спартак/ЦСКА/Краснодар/Локо/Динамо/Чертаново/Рубин),
0.6 (СШОР/спортшкола), 0.3 (иначе). `proj_level` — бины `pers_score`:
[0,40] низкий, [40,60] ФНЛ-2, [60,80] ФНЛ, [80,100] РПЛ. Эвристика прозрачная,
смещена в сторону голов, задокументирована.

Плюс ручные проверки циркулярности при добавлении фич: корреляция новой фичи с

## 12. Известные ограничения

- **Маленький, шумный таргет.** Прорывов исторически — пара сотен. Травмы, форма,
  решения тренеров в цифрах не отражены. Это ранжирование потока, не предсказание
  одной карьеры.
- **Только 2 пригодные тестовые когорты** — доверять сравнению «модель vs скаут»
  можно на 1999–2000, дальше пул кандидатов вырожден.
- **`recognition` полу-циркулярен** (corr 0.70 с рыночной стоимостью) — на проде
  работает, только если для новых игроков статьи в вики реально появляются до
  cutoff (верно в основном для уже раскрученных).
- **Данных младше U15 почти нет** — фичи в 11–14 лет разреженные.
- **`academy_club`** — свободный текст `formerClubsNote`, поэтому
  `academy_conversion_rate` слабый.
- **Рыночная стоимость на cutoff** в основном пустая (нужен эндпойнт
  `marktwertverlauf`).
- **youfl.ru / youthleague.ru** недоступны — ЮФЛ-контекст держится на строках
  `RUJL` из tmapi и таблицах Wikipedia.
